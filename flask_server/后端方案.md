# Flask 后端方案

## 目标

把现在仓库里的前端 Three.js 页面、Arduino 单片机和手机上传流程接起来，形成一条可联调、可展出的后台链路：

`Arduino 串口 -> Flask -> Socket.IO -> 前端`

同时补上：

- 手机 X 光上传页
- 会话隔离
- 海报生成与展示
- 重置与二维码刷新

## 设计原则

1. 先保证本地闭环能跑，再逐步接入 AI。
2. 串口失败不能拖垮整个服务。
3. 所有会影响展览流程的状态都由 Flask 后台统一持有。
4. 前端暂时没实现的事件也先在后台保留，后续扩展不用推翻结构。

## 状态流

- `IDLE`：待机，显示上传二维码
- `GUIDE`：用户按按钮后进入引导阶段
- `EXPERIENCE`：引导结束后进入体验阶段
- `TRANSITION`：体验结束后的收束阶段
- `WAITING`：等待海报生成
- `SHOWING`：展示海报和海报二维码

## 串口桥接

- 自动识别 Arduino 常见串口描述：`Arduino`、`CH340`、`USB Serial`
- 串口格式兼容：
  - `S1:xxx,S2:xxx,S3:xxx,S4:xxx,B:xxx`
  - 扩展格式里多出来的字段会被忽略
- 优先使用 Arduino 已算好的 `B`
- 如果没有 `B`，则按文档重算：
  - `chest = S1 - S2`
  - `waist = S4 - S3`
  - `raw = chest * Wc + waist * Ww`
  - `blend = clamp(raw / threshold, 0, 1)`

## Socket.IO 设计

- `sensor_data`
  - 实时推送传感器与 `blend`
- `state_change`
  - 推送当前流程状态
- `session_update`
  - 推送新的上传二维码与链接
- `poster_ready`
  - 海报生成完成后通知前端
- `reset`
  - 整轮体验回到待机

## 上传与会话

- 每轮体验持有一个 `session_id`
- 待机右下角二维码指向 `/upload?session=<id>`
- 用户按开始按钮后会话立即锁定
- 锁定后旧二维码继续访问会返回“已失效/已锁定”
- 重置后生成新 `session_id`，旧链接自动失效

## AI 策略

- X 光分析：
  - 如果配置了 `GEMINI_API_KEY`，尝试调用 Gemini 提取脊柱点
  - 如果调用失败，回退到内置脊柱点，保证上传流程不中断
- 海报生成：
  - 当前版本先用 Pillow 本地生成占位海报
  - 这样不依赖外部图像接口，现场更稳
  - 后续如果你要接真实 AI 图像生成，只需要替换 `render_poster()`

## 为什么这样拆

- 你现在最急的是“把展览流程跑通”，不是把 AI 一次做到最满。
- 串口、状态机、二维码、上传和海报查看先稳定，后面换 AI 实现成本很低。
- 这套结构对展前联调更友好，出了问题也容易单独定位是哪一段断了。

## 建议联调顺序

1. 先启动 Flask 服务，访问 `/status`
2. 打开前端，确认 `Socket.IO` 已连接
3. 接 Arduino，看 `sensor_data` 是否进来
4. 测试上传页 `/upload`
5. 通过前端按钮或 `button_press` 进入 `GUIDE`
6. 手动调用 `/generate` 看海报和二维码是否生成
7. 最后测试 `/reset` 是否能完全回到待机
